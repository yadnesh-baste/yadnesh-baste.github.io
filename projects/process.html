From IT request to portfolio decision

Departments ask IT for more than the budget can fund. This process makes sure every request arrives complete, is assessed the same way, and gets a decision the requester can understand.

This is an anonymised reconstruction of a common demand-management pattern, written from public practice and my own experience. It contains no internal PowerCo documents, names or figures.

The problem it solves

In a growing company, IT requests come in by email, in meetings and through tickets. Many lack the basics: what problem they solve, who benefits, by when. Effort gets estimated before the scope is clear, priorities follow whoever pushes hardest, and requesters rarely hear why their request waited. At PowerCo I coordinated 15+ demands from seven departments, and the process had to work the same way for all of them.

The process

Open the .bpmn file in demo.bpmn.io or Camunda Modeler to inspect or edit it.

Design decisions

Completeness before effort. Demand management checks a request before anyone estimates it. Incomplete requests go back to the requester with the missing points named, which keeps architects' time for requests that can actually be judged.

Each lane owns one kind of judgement. The requester owns the business case, demand management owns completeness and scoring, architecture owns feasibility and risk, the board owns the decision. Nobody decides on information they don't own.

"No" is not a dead end. Requests that aren't funded are recorded with a review date and the requester is told why. That keeps the backlog honest and stops the same request from returning through a side door.

The process can change itself. At PowerCo I also created a change process for updating the lifecycle process itself, so improvements follow a defined route instead of ad-hoc edits. A process nobody can update gets bypassed.

What it changed in practice

Modelling the process in BPMN made hand-offs visible that had lived in people's heads, and gave product owners one reference. I created training for them on the process, including an AI-assisted interactive version so they could practise it before using it for real.
